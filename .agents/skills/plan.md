## 目标用户与使用场景

谁会用：

- 学生党（学习时需要专注音乐）
- 程序员（写代码时想要不被打扰的背景音）
- 焦虑的人（需要安抚音乐）
- 运动爱好者（需要节奏感的音乐）
- 失眠人群（需要助眠音乐）

什么时候用：

- 开始学习/工作前
- 睡前
- 感到焦虑时
- 运动前
- 任何需要背景音乐但不知道选什么的时候

## MVP 核心流程

用 4 步描述完整流程：

1. 用户输入 - 用户在输入框里说几句话，比如「我现在很困，但还要学 2 小时高数」
2. AI 规划 - 系统思考几秒，生成一个音乐方案（模式、时长、节奏变化、为什么这样安排）
3. 方案展示 - 页面上显示这个方案，粒子效果跟着变化
4. 开始播放 - 用户点击「开始」，进入播放界面，粒子跟着状态律动

## 功能优先级

### 必做功能（必须在 2 小时内完成）

1. 用户输入框 - 能输入文字
2. AI 规划结果展示 - 显示模式、时长、方案说明
3. 粒子视觉效果 - 根据状态变化（漂浮、聚合、律动等）
4. 开始/停止播放的交互
5. 本地 mock 数据（如果来不及接真实 API）

### 加分功能（有时间再做）

1. 接入真实的 MiniMax AgentPlan API
2. 播放时间线可视化
3. 多种预设场景（快速选择）
4. 音量调节
5. 简单的音乐播放（用音频文件或 YouTube 嵌入）

### 放弃功能（现在不做）

1. 真实音乐库（太复杂，用文字描述方案就行）
2. 用户账户系统
3. 历史记录
4. 分享功能
5. 复杂的粒子物理效果
6. 手机端适配

## 页面/模块拆分

只需要 1 个页面，分成 3 个部分：

### 1. 输入区

- 一个大的输入框
- 几个快速输入的按钮（「学习」、「睡觉」、「运动」、「安抚」）
- 一个「生成方案」按钮

### 2. 方案展示区

- 当前模式标签（专注/睡眠/安抚/运动/白噪音）
- 推荐时长
- 方案说明（为什么这样安排）
- 播放计划时间线（简单的文字描述）

### 3. 粒子背景区

- 全屏粒子效果
- 根据状态变化视觉效果

## 推荐技术方案

### 技术栈选择（为什么这样选）

技术 为什么选它 React + Vite 项目模板已经准备好了，启动快，代码简单 Tailwind CSS 写样式快，不用想太多，能快速做出高级感 p5.js 做粒子效果最简单的库，能快速实现视觉效果 mock 数据 + localStorage 不用连后端，2 小时内能搞定

### 为什么这样最稳？

1. 都是前端技术，不需要后端、数据库
2. 用 mock 数据，不用等 API 对接
3. 都是成熟的库，不容易出问题
4. 单页应用，结构简单

## 开发顺序（按 1、2、3、4... 来）

第 1 步（30 分钟）：基础页面搭建

- 初始化项目（用模板）
- 做输入区和方案展示区的简单 UI
- 不用粒子，先把页面骨架搭好

第 2 步（30 分钟）：粒子效果实现

- 加入 p5.js 粒子
- 实现基础的粒子漂浮效果
- 实现 2-3 种状态的视觉变化

第 3 步（30 分钟）：核心流程 + mock 数据

- 实现输入 → 展示方案的流程
- 写几套固定的 mock 方案数据
- 不用真实 AI，先让流程跑通

第 4 步（20 分钟）：交互优化

- 点击「生成方案」有反馈
- 点击「开始播放」状态变化
- 粒子跟着状态变化

第 5 步（10 分钟）：美化和检查

- 调整颜色（暗色系）
- 检查所有功能正常
- 准备 Demo 演示
